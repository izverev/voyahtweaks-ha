# VoyahTweaks в Home Assistant

Пользовательская интеграция (`voyahtweaks-ha`) получает телеметрию Voyah Free из API
`https://app.voyahtweaks.ru/api/v2/` и создаёт сенсоры, бинарные сенсоры и GPS-трекер.
К ней прилагается тёмная Lovelace-карточка **VOYAH FREE**.

Управление автомобилем (замки, окна, люк, багажник, климат, зарядка, охрана, поиск). 
**выключено по умолчанию** и включается отдельной опцией (см. «Управление автомобилем»).

## Установка

### Вручную
1. Скопируйте папку `custom_components/voyahtweaks-ha` в `/config/custom_components/`.
2. Скопируйте `www/voyahtweaks-ha-card.js` в `/config/www/`.
3. Перезапустите Home Assistant.

### Через HACS
Добавьте репозиторий как «Custom repository» (категория «Integration»). Файл карточки всё
равно нужно скопировать в `/config/www/` вручную (см. ниже).

## Настройка

**Настройки → Устройства и службы → Добавить интеграцию → «VoyahTweaks»**

1. Введите логин и пароль от app.voyahtweaks.ru.
2. Если сервис просит подтвердить e-mail, введите код из письма. Чтобы получить код ещё раз,
   отметьте «Отправить код ещё раз» и нажмите «Отправить».
3. VIN берётся из профиля (`/api/v2/me`) автоматически. Если в профиле несколько автомобилей,
   интеграция предложит выбрать один (отключённые автомобили игнорируются).

**Пароль не сохраняется.** Он используется один раз при входе и при повторной авторизации, после чего
отбрасывается. В записи конфигурации хранятся только токены: access, refresh и `x-device-token`.
Продление сессии идёт исключительно по refresh-токену. Когда сервер отвергает refresh-токен,
Home Assistant запускает повторную авторизацию, и пароль потребуется ввести снова.

Токены обновляются автоматически; при HTTP 401 выполняется одно обновление токена и один повтор запроса.

### Параметры (Настроить)

| Параметр | По умолчанию | Примечание |
|---|---|---|
| Интервал опроса | 5 минут | 1, 2, 5, 10, 15 или 30 минут. Чаще раза в минуту опрос невозможен. |
| Порог устаревания | 10 минут | После этого возраста телеметрия считается устаревшей. |
| Подробная диагностика батареи | вкл. | Напряжения ячеек (макс/мин/разброс), изоляция. |
| Сенсоры отдельных ячеек | выкл. | До 9 температур и 90 напряжений, отключены в реестре по умолчанию. |
| Разрешить управление автомобилем | выкл. | Без этой опции ни одна команда не отправляется. |
| Разрешить запуск без ключа | выкл. | Работает только вместе с предыдущей опцией. |

Изменение параметров перезагружает интеграцию, повторный вход не нужен.

## Как работает «сон» автомобиля

Успешный ответ API не означает свежих данных. Поэтому состояния разделены и не подменяют друг друга:

| Сущность | Что означает |
|---|---|
| Доступность API | Ответил ли сервер на последний опрос. Атрибут `last_error` содержит причину. |
| Автомобиль онлайн | Поле `online` из телеметрии как есть. |
| Телеметрия актуальна | Возраст `last_seen` не превышает порог. Неизвестно, если `last_seen` отсутствует или не разобран. |
| Возраст телеметрии | `сейчас − last_seen`. |
| Последнее обновление автомобиля | Значение `last_seen`. Атрибуты показывают, изменилось ли оно с прошлого опроса. |
| Последний успешный опрос API | Время последнего успешного HTTP-ответа. |

Что происходит, когда автомобиль спит или API недоступен:

- последние значения **не обнуляются** и сущности **не становятся недоступными**;
- последняя действительная GPS-позиция сохраняется;
- состояние сохраняется на диск и восстанавливается после перезапуска Home Assistant;
- при ошибках API включается ограниченный backoff (интервал удваивается, максимум 30 минут;
  при HTTP 429 учитывается `Retry-After`), после успеха интервал возвращается к выбранному;
- ручное обновление не может обойти ограничение «не чаще раза в 60 секунд».

## Сущности

Сенсоры создаются только для тех полей, которые реально есть в телеметрии, и добавляются позже,
если поле появится.

- **Батарея и движение:** заряд (SOC), SOH, SOE, остаток энергии, запас хода, реальный запас хода, пробег,
  скорость, напряжение и ток HV-батареи, температуры батареи (средняя/мин/макс), 12 В батарея, топливо.
- **Зарядка:** состояние зарядки (бинарный), кабель подключён, тип зарядки (нет/AC/DC),
  мощность, время до окончания (в минутах).
- **Кузов:** четыре двери, четыре окна (закрыто/приоткрыто/открыто), багажник, замок, люк, охрана.
- **Климат:** удалённый климат, охлаждение, обогрев, система климата, температура в салоне и снаружи.
- **GPS:** `device_tracker` — только при `power.location.gps_valid == true` и корректных координатах.
- **Диагностика:** напряжения ячеек, разброс, изоляция, статусные сущности из раздела выше.
- **Шины:** восемь сенсоров с понятными именами: «Давление правой задней шины», «Температура левой передней шины»
  и т. д. Исходные ключи API: `bcm_tyre{LF,RF,LR,RR}{Pressure,Temp}`, где LF/RF/LR/RR — позиция колеса
  (левое переднее, правое переднее, левое заднее, правое заднее), а Pressure/Temp — тип измерения.
  Температура в °C. Единица давления неизвестна (приложение показывает голое число с одним знаком),
  поэтому давление выводится без единицы.

Значения, смысл которых не подтверждён, не угадываются: сенсор показывает «неизвестно», а исходное число
лежит в атрибуте `raw_value`.

## Управление автомобилем

Список команд и форма запроса взяты из JavaScript приложения Voyahtweaks. Включение:
**Настроить → «Разрешить управление автомобилем»**. Действует также флаг `can_manage` из профиля:
если аккаунту управление недоступно, сущности не создаются.

> **Безопасность.** Команды реально уходят автомобилю. Любой пользователь Home Assistant, у которого есть доступ
> к этим сущностям, сможет открыть машину. Включайте, только если доверяете всем пользователям.
> «Запуск без ключа» (`keyless_start`) вынесен в отдельную опцию, потому что он может завести автомобиль.

| Сущность | Команды (`cmd`) |
|---|---|
| Замок (`lock`) | `door_lock`, `door_unlock` |
| Окна (`cover`, все четыре сразу) | `windows_open`, `windows_close` |
| Люк (`cover`) | `sunroof_open`, `sunroof_close` |
| Багажник (`cover`) | `tailgate_open`, `tailgate_close` |
| Кнопки (`button`) | `search_start` (сигнал и аварийка), `search_stop`, `hazard_on`, `windows_vent`, `sunroof_vent`, `keyless_start` |
| Охрана (`switch`) | `sentry_on`, `sentry_off` |
| Зарядка (`switch`) | `charge` с `op`: `start_now`, `stop`, `schedule`, `schedule_cancel` |
| Климат (`climate`) | `climate` с `mode`: `off`, `temp`, `rapid_cool`, `rapid_heat` |

Как это работает:

- Команда отправляется как `{"command_id": <uuid>, "cmd": ..., ...параметры}`, затем статус опрашивается каждые 1,5 с
  (`pending → sent → completed | failed | no_response | expired`), до 90 секунд. Если статус не `completed`,
  Home Assistant показывает ошибку.
- Одновременно выполняется только одна команда.
- После команды сущность сразу показывает ожидаемое состояние. Реальные данные подтянутся при следующем опросе,
  но не раньше чем через 60 секунд после предыдущего запроса (лимит API сохраняется и для команд).
  Если автомобиль спит и телеметрия не изменилась, сущность вернётся к реальному состоянию.
- Изменение целевой температуры в выключенном климате **не запускает** климат, значение только запоминается.

Сервисы (в «Инструментах разработчика → Действия»):

```yaml
action: voyahtweaks-ha.climate_start
target: {entity_id: climate.voyah_klimat}
data: {mode: temp, temperature: 22.5, seat_fl: 2, seat_fr: 0, glass_heat: true, runtime: 15}

action: voyahtweaks-ha.charge_start      # цель по умолчанию 80 %
target: {entity_id: switch.voyah_zaryadka_upravlenie}
data: {max_soc: 90}

action: voyahtweaks-ha.charge_schedule
target: {entity_id: switch.voyah_zaryadka_upravlenie}
data: {start: "23:00", end: "06:00", max_soc: 80, cycle: true}
```

(`entity_id` у вас будут свои, смотрите их на странице устройства.)

## Карточка VOYAH FREE

1. **Настройки → Панели → Ресурсы** (включите расширенный режим): добавьте ресурс
   `/local/voyahtweaks-ha-card.js` с типом «JavaScript-модуль».
2. Добавьте на дашборд карточку:

```yaml
type: custom:voyah-free-card
```

Необязательные параметры: `name` (заголовок), `device_id` (если автомобилей несколько),
`entities` (ручная подстановка сущностей по ключу, например `soc: sensor.my_soc`).

В карточке есть блок шин и кнопки «Закрыть/Открыть», «Найти», «Багажник». Кнопки появляются только если включено
управление; открытие замков и багажника просит подтверждение. Кнопки вызывают сервисы Home Assistant, а не API напрямую.

Карточка сама находит сущности интеграции через реестр, поэтому не зависит от языка интерфейса и
`entity_id`. К API она не обращается. При устаревших данных показывается предупреждение вида
«Данные не обновлялись 18 минут. Автомобиль может находиться в спящем режиме.», а последние значения остаются.

## Структура

```text
custom_components/voyahtweaks-ha/   интеграция
www/voyahtweaks-ha-card.js          карточка
tests/                             автотесты (pytest + node)
```

Запуск тестов: `cd tests && PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q && node card_test.js`.

Переменная `PYTEST_DISABLE_PLUGIN_AUTOLOAD` нужна, если в том же окружении стоит Home Assistant:
его pytest-плагины подхватываются автоматически и ломают тесты на заглушках.
